# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Claude Code **mod** (plugin with hooks, not a standalone app): a docked pane of GitLab issues and MRs assigned to the user, drawn as status-coloured cards. Pressing a card whose Claude is not running sets the `choosing` atom, and the card's last row turns into `open: [window] [tab] [split] [here] [×]` (`openAt`): a new Ghostty window, a tab, a split to the right of the focused terminal in the front window's selected tab (stored with that tab's id; the tab keeps its title), or here (only when this session's cwd, the `cwd` atom, is in the card's clone; puts the card url in this prompt with `$.prompt.fill`, or `/resume <sid>` in place of the draft when the card has a saved session (`resumeOf`) that is not this one; the url case stores `card:<key>` as `{ sid: <this session>, tab: '', in: 'here' }`, dropping any other `here` key of this session, so the card joins Working at once; `cardStatus` never deletes the key of the running session, and `isCardWindow` treats only `window` (or no `in`) as a card window). The last choice is stored as `ui:openIn` and drawn bold (the order is fixed: here, split, tab, window). There is no `package.json`, bundler or build step; the engine loads `hooks/register.tsx` directly.

## Commands

```sh
claude plugin validate .   # manifest, hooks and the `types/` state contract; must say "Validation passed"
claude plugin test .       # runs every *.test.ts / *.test.tsx under the folder
claude --plugin-dir .      # load the mod for one session
npx -y -p typescript@5.9.3 tsc --noEmit -p .   # typecheck; must print nothing
```

- `claude plugin test` takes only a folder; it has no filter flag.
- Neither `validate` nor `test` checks types; only `tsc` does. `tsconfig.json` extends `.claude-plugin/types/tsconfig.json`, which the engine writes (with the `claude-code` and `claude-code/testing` declarations) when it loads the mod; it is git-ignored and refreshed by each Claude Code update. It is strict with `noUncheckedIndexedAccess`: destructure with a default or guard, and in tests take a list's head through `first`, not `[0]`.
- `bun` and `vitest` are not set up here. Tests import from `claude-code/testing`, which exists only inside the engine's test runner. The test `$` is typed, so a `command.run` in a test spreads `TYPED_RUN` for `origin` and `presentation`.
- In the pane, `/wip-wall` refreshes and opens it.

## Architecture

- `hooks/register.tsx`: the only file with atoms and hooks (`gitlab.ts` keeps one module-level cache, the detected settings). Registers `session.start`, `command.run` (`wip-wall`, `wip-wall mock` shows `hooks/mock.ts` cards) and the `ui.render` hook for the `wip-wall` pane. State lives in `atom`s keyed `{ plugin: 'wip-wall', key }`; writes via `update` redraw the pane. Issues come from `glab api --paginate --output ndjson`, mentions from pending `mentioned` and `directly_addressed` todos (`mentionsOf`; drawn as a Mentions section above the cards, deduped against assigned cards, which get an `@` instead; a failed todos call only adds `mentions: ...` to the error bar), MRs from one `glab api graphql` query (`mrOfGraphql` maps nodes to the REST-shaped `Raw`), local clones from `find` under the detected root, and session liveness from `ps` (a card is open while a process's argv holds its `sid` (read with `ps -o pid=,command=`; the argv of a pid that Claude's own session file lists is ignored, since that process may have moved to another session id after `/clear`), or while Claude's own `<config>/sessions/<pid>.json` names that `sessionId` and the pid's start time, read with `TZ=UTC ps -o lstart=`, equals its `procStart`, which catches a `claude` started by hand that used `[here]`; that file format is Claude Code's, undocumented, so a failed read only drops those sessions; Ghostty is only asked when a card is pressed). `$.store` (persists across sessions) maps `card:<key>` to `{ sid, tab }` so a card reopens or resumes its own Claude session.
- `hooks/gitlab.ts`: everything that talks to GitLab through `glab`: `settingsOf` (detects glab, host, clone root, sessions dir once), `run`, `listOf`, `mrsOf` (one GraphQL connection, paged: `assignedMergeRequests`, or `reviewRequestedMergeRequests` filtered to `REVIEW_STATES` (unreviewed, review started, unapproved)), `pendingMentions`, `boardOf` (24 h `board:` cache) and `fetchBoard`, which returns issues, MRs, review requests, mentions and a `failures` record (`mrs`, `reviews`, `mentions`) so a caller trusts only the sources that were fetched. An issues failure still throws.
- `hooks/sessions.ts`: everything about the Claude session behind a card, with no atoms: `cardStatus` (open, resumable and this-session cards from `ps`, transcripts and the `card:` keys; deletes dead keys through `canWrite`), `pruneCardSessions`, `isCardWindow`, `focusRunning` (select the tab of a card whose sid runs) and `openCardSession` (here, window or tab). `register.tsx` passes it `() => !mocking` and writes the atoms from what it returns.
- `hooks/view.tsx`: how a card, a mention, a filter picker and a rule are drawn (`cardView`, `mentionView`, `picker`, `rule`, `foldRule`, `rowsOf`). It never sees `$`: `register.tsx` builds a `Look` (the engine's elements, the theme, widths and everything already read from atoms) and an `Act` (handlers that close over `$`) and passes them in. Every Button key (`open:<k>:<n>`, `choose:<k>:<place>`, `hide:`, `restore:`, `web:`, `mrweb:` (`MR !N` on the MR line, `MR` in a compact row; opens that MR), `note:`, `mr:`, `*:toggle`) lives here and is asserted in `pane.test.tsx`; only the header's `legend:toggle` (`[i]`, the marker legend under the header), `compact:toggle` (`[c]`), `theme` (`[t]`), `refresh` and `retry` stay in `register.tsx`. `cardOfMention` (a mention as a card, for opening it) lives in `board.ts`.
- `hooks/board.ts`: pure functions with no engine imports (`toCards`, `paneOf` (every filter, count and section the pane draws), `viewOf`, `groupsOf`, `reposOf`, `rankOf`, `isDone`, `titleOf`). Status labels are normalised here; an MR joins the issue whose number its branch names. Unit-tested directly.
- Reviews: `reviewsOf` (in `board.ts`) turns review requests into `kind: 'mr'` cards with their own `MrRef` (status from a label, else `review`, which has its own colour in each theme; `by` is the MR author, drawn as the bare name, in the text colour, in a box and in `[c]`), dropping any MR also assigned (raw refs, since `toCards` folds MRs into issues). They live in the `reviews` atom, never in `cards`, so they stay out of Status chips, counts, `unmatched`, `doneLeft` and "Nothing assigned"; `paneOf` draws them in a `Requests · N` fold (`ui:reviews`) under Mentions, filtered by Project and Updated, joins them to Working, Dismissed and the mention dedupe. A `!` hide is pruned only when both MR queries succeeded; the `reviews` failure also blocks `pruneCardSessions`. `cache:board` carries `reviews` (an older cache reads as `[]`).
- Folds: Working and every section draw a `foldRule` (label with its count, `[hide]`/`[show]`); keys `working:toggle` and `sec:<name>:toggle` (`sec::toggle` for the unnamed `Cards` section). The closed ones live in the `folded` atom (ids `working`, `sec:<name>`), remembered as `ui:folded`. Mentions, Requests and Dismissed keep their own atoms.
- Compact: `[c]` in the header (`compact` atom, `ui:compact`) swaps `cardView` boxes for `cardRow` lines (same `open:<k>:0`, `web:` and `hide:` keys; the chooser drops below the row) in Working, Reviews and the sections, and `mentionView` for `mentionRow` (no body). A row is the title, then the tail, then the status (the `web:` link), the age padded to 3 (`ageOf` never returns more than 3 characters: months stop at `9mo`, from 300 days it counts years, capped at `99y`) and `✕` at the right edge, so every status ends in one column and the ages line up. A review row draws its status like any other (the fallback `review` included, so the slot is always filled and sits in the same place); its `MR` link opens the same MR. Parts of a row are split by a space, no ` · ` (mention rows too). The tail is an `MR` link (`mrweb:`, opens that MR) when the card has one, tinted by the worst MR flag (`worstFlag`: first bad, else first warn, else first good; muted when none) in place of the flag's text, then the review author's name (no `by`, in the text colour), `@`, the due date and `↓` last, so the branch mark always sits just before the status. Dismissed stays boxes.
- Sort: the last Filters row, `Sort : [default] [latest]` (the `default` label is the `status` id, renamed so it does not read as the Status filter) (a `picker` collapsed to the current choice and `+1 more` like the other filters; atom `sortMenu`; keys `sort:menu`, `sort:status` and `sort:latest`; `latest` atom, `ui:latest`), passes `latest` to `paneOf`, which then sorts each section by newest `updated` instead of board status rank first; Working, Requests and the sections themselves keep their order. It is a filter row, not a header setting.
- Markers: `markOf` (`view.tsx`) draws `○` none, `◎` resumable (a saved session), `◉` open and `●` here: one Unicode block and one cell box, ink weight rising 16, 27, 39, 53, so a stacked column reads as one ramp. The here card pulses `●` and `◉` through `pulse.tsx` in the box view and in `[c]` (`cardRow` renders the `Client` itself; without `Client` it is a still `●`). Pick a new marker from the measurements in `GLYPHS.md`, not by eye: `widthOf` matching is not enough, glyphs from other Unicode blocks come from other fonts and draw heavier or lighter.
- `hooks/themes.ts`: `THEMES` (`catppuccin`, `neon`, `tokyo-night`, `rose-pine`, `gruvbox`, `cyberpunk`, `latte`, cycled in that order; `latte` is the one for a white terminal, measured on `#ffffff` with `ink` white for the chips); each maps lowercase status to a colour. Colour means status only: the picked Project, Repo, Updated and Status `all` chips sit on `muted`, so no filter chip reads as a status. Measured on a `#222222` terminal, every status, `text`, `muted`, `good`, `warn` and `bad` keeps at least 4.5:1 and `faint` 3.5:1; a colour that missed was lifted toward white by the smallest step that passes, so a new or changed colour should be checked the same way. `board.ts` knows no colours: `register.tsx` resolves the theme from the `theme` atom and `view.tsx` turns a status into a colour (`colorOf(theme, status)`), and `board.test.ts` reads `THEMES.catppuccin` directly. Pressing `[t]` at the header's right cycles themes; the `[i]` legend names the current one (`t: <name>`).
- `hooks/spinner.tsx`: `Client` module (runs on the surface's own clock, so the pane does not redraw to animate). The header's `↻ <age>` is plain text inside one `Button` (a `Client` cannot sit in a `Button`), so the age only refreshes when the pane redraws. The pane falls back to static text when `'Client' in els` is false; the test harness does expose `Client`, so tests see a `Client` node (assert on its `props.module`), not the fallback text.
- `types/index.d.ts`: the `PluginState` contract. Every atom used in `register.tsx` must be declared here or `validate` fails.

## Gotchas

- Splitting `register.tsx`: a helper that takes `$` and lives in another file must be a `function` declaration (`export async function f($: Dollar)`), not a const arrow, or the module fails to load ("$ is passed to ... a name bound to a function expression"). Atoms must be declared in the same file that calls `read` or `update` on them, so an extracted module never touches atoms: it takes values and returns values, and `register.tsx` writes the atoms. JSX in an imported `.tsx` is fine; its Buttons still need keys.
- Every `<Button>` needs a `key` when its child is not a single string, or the engine skips the whole `ui.render` and the pane draws nothing. The failure shows only as a dim `wip-wall:` line in the transcript or as test failures.
- Each successful `refresh` saves cards, mentions, branches, clones and board orders as `cache:board`; `session.start` draws that (`loadCache`, with `loadedAt` = its time, so the age button shows how old it is) before the first refresh. The spinner shows only when there is no cache and no refresh has finished (while `loadedAt` is 0 and `cards` is empty, `ui.render` also draws `cache:board` straight from `$.store` through `savedBoard`, so a session whose atoms were reset has no spinner gap); a loaded board with no cards shows "Nothing assigned to you". `cache:board` is not a `board:` key. It carries `v: CACHE_VERSION`; bump that whenever `Card`, `Mention` or the cached fields change shape, or an old cache can crash the first render.
- `pane.test.tsx` `boot()` mocks the engine calls the module makes; a new `$` call in `register.tsx` needs a matching `on('<event>', ...)` mock there, otherwise `refresh` throws and a red error line appears in the pane.
- Theme colours are asserted as hex in `pane.test.tsx`; changing `themes.ts` values means updating those assertions.
- While this folder is loaded as a plugin (`CLAUDE_CODE_PLUGIN_DIRS` or `--plugin-dir`), `Edit` and `Write` on its files fail closed in auto permission mode with "classifier gave no verdict"; an allow rule does not help. Edit in acceptEdits or default mode.
- `settingsOf` detects `glab`, host, clone root (no default: only `WIP_WALL_ROOT` or the saved `ui:root`) and sessions dir once per load through one `sh -c`; override with `WIP_WALL_GLAB`, `WIP_WALL_HOST`, `WIP_WALL_ROOT`. Ghostty on macOS is still required (`osascript`).
- `hooks/marquee.tsx` is a `Client` module like `spinner.tsx`; the pane's `marquee` atom holds the card key whose cut MR line is scrolling.
- GraphQL enums come back upper-case (`SUCCESS`, `NOT_APPROVED`) and `notes(last: 10)` is oldest first; `mrOfGraphql` lower-cases and reverses to match what `board.ts` expects.
- `dirs` maps a GitLab project to a clone: `scanDirs` reads each clone's `remote.origin.url` in one `sh -c` and `dirsOf` keys the lowercased project path (`projectOf` accepts only the configured host). Look clones up with `dirOf(dirs, card)`, never `dirs[card.repo]`.
- Folder names are never trusted. Only a clone with no remote at all is also keyed `:<folder>`, and only when that name is unique. A clone whose remote could not be read (`git config` failed, printed as `!`) is not findable at all. Two checkouts of one project resolve to the first by sorted path. A path containing a tab is skipped.
- A card whose project has no clone gets the "No local clone" toast on purpose, even when a same-named clone from another group exists: opening it would start Claude in the wrong repository. A moved GitLab project whose clone keeps the old remote url needs `git remote set-url`.
- Text from other people goes through `clean` in `board.ts` (control characters become spaces) and links open only through `openWeb` / `isWebUrl` (http and https).
- `/wip-wall mock` is guarded: `open`, `openWeb`, `dismiss` and `restoreOne` only toast while `mocking` is true, so a mock card can never start a session or write a `hide:` key to the persistent store. `hidden` is deliberately not cleared (`syncHidden` only runs at `session.start`).
- Every write of board data (`cards`, `mentions`, `boards`, `dirs`, `local`, `live`, `resumable`, `here`, `error`, `loadedAt`) goes through `applyBoard($, source, part)`, which re-checks its source before each atom: `mock` and `reset` (leaving mock) always write; `real` (refresh, liveness) writes only while not mocking; `cache` only while not mocking and `loadedAt` is 0. A refused write stops the caller (`reload` returns, even between phases, so `cards` may be written while `boards`, `dirs` and `loadedAt` are not); `reload`'s `catch` writes its error through it too. `mocking` stays a plain module variable so those re-checks after an `await` stay synchronous. `reload` writes in phases (cards, mentions and a first `loadedAt`, then boards, dirs, then local, error and the final `loadedAt`) so the first paint does not wait for the clone scan. `applyBoard` checks `mayApply` first and then skips a write whose value equals the atom's (`differs`, JSON compare), so a cache load followed by an identical refresh does not redraw the pane; `loadedAt` always changes.
- Inside `register.tsx` the engine only accepts `$`-taking helpers declared directly (a function or a const arrow at the top of the file); helpers in another file must be `function` declarations (next note). A wrapper such as `const open = guard(async ($) => ...)` makes the module fail to load, so the four `mocking` guards stay written out.
- `isWebUrl` accepts only `http(s)://` with no whitespace or control characters; a newline in a url would submit itself into the Claude prompt `open` types.
- `dueOf` draws a due date as `→3d` (ahead, muted), `→0d` (today, warn) or `←2d` (late, bad), in the same units as `ageOf` (`spanOf`: `d` under 14 days, then `w`, `mo` up to `9mo`, `y` capped at `99y`), so it never passes 4 columns and `ageOf` never passes 3.
- `widthOf` counts by unicode property (`Emoji_Presentation` 2, flags 1 each, modifiers and joiners 0, `✓ ✗ ★` 1). Known ceiling: a ZWJ family counts every emoji (4, drawn as 2). The `ponytail:` line in `board.ts` names the upgrade path.
- Accepted risk: `open` types a mention's note url into the Claude prompt, so text from whoever mentions you reaches a session that has your permissions. The user must press Enter, so nothing is submitted for them.
- Text reaches the screen only through `toCards`, `reviewsOf`, `statusOf` and `mentionsOf`, which all call `clean`; `mrOfGraphql` output goes through `toCards`, and its pipeline and merge values are map keys. A new displayed field must call `clean` too.
- `glab api --paginate` without `--output ndjson` prints concatenated arrays that `JSON.parse` rejects.
- A failed MR query does not fail `refresh`: issue cards still draw without MR lines and the error bar reads `merge requests: ...`; a failed issues call still fails the whole refresh.
- `hide:<key>` stores the card's `updated` at dismissal. After each successful refresh `pruneHidden` deletes every `hide:` whose card or mention is gone or has a newer `updated` (`staleHides`), but never one whose source query failed: MR keys (`!`) wait for a good MR query, mention keys (`@`) for a good todos query.
- A session whose id is the `sid` of a `card:` key opened `in: 'window'` (or with no `in`, from before tabs were a choice) registers `/wip-wall` but opens no pane and starts no polling; `/wip-wall` there loads dismissals, refreshes, opens the pane and starts polling once (`poll`). `openSession` stores `{ sid, tab, in }` before launching (restored or deleted if Ghostty fails) so the new session already finds itself at `session.start`. `boot()` in `pane.test.tsx` takes `args: null` to skip the command run. The same holds for a session whose cwd is outside the clone root (`insideRoot`; an unknown root or a failed detect also keeps the pane closed, so nothing is read before a clone folder is set; `/wip-wall` still opens it); the `/clear` restart passes `start($, true)` to skip that check, since it only runs while the pane is open, and `start` skips both checks when a `wip-wall` pane is already open (a plugin reload runs `session.start` again and would otherwise leave the pane drawn from cache with no polling). `boot()` defaults its cwd to `FIXTURE_ROOT`.
- Working: cards in `live` (an open window or tab) plus `here` (the card whose `sid` or `prev` is this session's id, set by `liveSessions`, else the issue whose number starts this session's branch inside its clone (`branchCard`) when no other window runs it; pressing it only toasts, so a card resumed here never gets a second terminal) are drawn in a Working section above Mentions, ignore every filter and leave the normal sections (the `here` card, the one that pulses, sorts first, then newest `updated`; `paneOf` takes it as `here`); picker counts still include them. `pane.test.tsx` fixtures have no running Claude by default (`alive` is the `ps` output and `liveFiles` the session file scan, both `''`); a test that needs one sets `alive`/`sessionId` and resets them in `finally`.
- `card:<key>` holds `{ sid, tab, in, at, prev }`. A window or tab for a card with a saved session starts a fresh `claude --session-id <new>` with `/resume <old>` typed and not submitted, so the person can resume or start new work; `prev` keeps `<old>` because a session that only resumed leaves no `<new>.jsonl`. `resumeOf` picks whichever of `sid` and `prev` has the newest transcript (`savedSessions` maps sid to mtime through `stat -f %m`). `liveSessions` (every 30 s) deletes one whose `sid` does not run and that `resumeOf` finds nothing for, and a full refresh (MRs and todos both fetched) deletes one whose card left the board unless its sid runs; both wait `LAUNCH_GRACE_MS` after `at` so a terminal still starting is not forgotten. Pressing a card whose sid runs selects its tab and never launches a second terminal; when the stored tab is gone (or `''`, a hand-started claude) `focusRunning` takes that session's `cwd` from `<config>/sessions/<pid>.json` and focuses the one Ghostty terminal whose working directory equals it (`FOCUS_CWD`), never guessing among several; otherwise the toast names the pid and tty. `open` checks this before the clone lookup, so a running card without a clone still focuses; a failed `ps` toasts and opens no chooser; the tab select has a 5 s `timeoutMs` and toasts when Ghostty does not answer. `runningSids` and `savedSessions` throw on a non-zero exit, so a blocked `ps` or `find` prunes nothing. The board set for pruning is the raw issue and MR references plus mention refs, not `toCards` output (which drops unlabelled issues and folds MRs into issues).
- `/clear` and `/resume` raise no `session.start` for a mod (the process continues under a new session id and every atom resets, module variables survive). A `session.end` hook with `reason` `clear` or `resume` waits `CLEAR_RESTART_MS` (up to `CLEAR_RESTART_TRIES` more times while the pane is not listed yet), then, when a `wip-wall` pane is open, resets `mocking`, `refreshing` and `polling`, cancels the old timers (`timers`) and runs `start($)`, the body of `session.start`. The filters (`group`, `tab`, `datePick`, `statusPick`) are read at `session.end` and handed to `start` through the module variable `carried`, which writes them back and skips the cwd repo pick. `carried` also holds the remembered view prefs (Mentions and Requests folds, legend, compact, sort, `folded`, theme, last open place) because `loadPrefs` restores them only after the wait, and `dismissedOpen`, `hidden`, `live`, `resumable` and `here`, which `syncHidden` and `syncLive` fill only later (without them dismissed cards reappear and Working empties for a moment). It is set at once (not after the wait) and `ui.render` reads it before the atoms, so the pane keeps both in the gap while the reset atoms still read their defaults; `start` clears it after writing the atoms, and the wait clears it when no pane ever lists. A `classic.SessionStart` hook does not work for this: the engine's `cc-plugin-sec-default` answers it before a mod's hook runs. In `pane.test.tsx`, `clock.after` is held like `clock.every` (`tick()` fires it) and `registered` counts `command.register` calls, which only `start` makes.
- Branch claim: `start` (every session with the mod, pane or not) runs `claimBranchCard`: `branchCard` over `cache:board` (`savedBoard`), and on a hit `claimCard` writes `card:<key>` `{ sid, tab: '', in: 'here', at, prev }` so the other panes see that hand-started Claude as running (through `<config>/sessions`). It keeps a resumable old session as `prev`, drops this session's other `by: 'branch'` keys, and writes nothing when the key already belongs to this session or to a running one, or when this session holds a card pressed `[here]` (the person's pick beats the branch). It runs at startup and again on every `prompt.submit` (one `git branch` each, fire and forget, the prompt is never held), so a branch switch moves the claim to the new card on the next prompt (`claimCard` drops this session's old `here` key, a card pressed `[here]` included), a branch that names no issue (`main`) releases the claim (`releaseBranchCard` deletes this session's keys marked `by: 'branch'`, never a card pressed `[here]`), and a session with no `cache:board` yet claims nothing. `pane.test.tsx` answers `prompt.submit` with `{ text }` and `branchName` overrides the `git branch` output.
- Setup gate: `gateOf` (`gitlab.ts`, no Ghostty probe) checks `glab`, GitLab login (`glab auth status`) and that the clone folder exists; `checkGate` in `register.tsx` runs it at the start of every `/wip-wall` and of `start`, calls `forgetSettings` first, and sets the module variable `ready` and the `gate` atom (`checking`, `blocked`, `ready`). `reload` returns while `!ready` and both timers skip, so nothing reaches GitLab or scans the root until it passes. `blocked` (and not mocking) makes `ui.render` draw only the title and `setupView` with no `close`, so no filters, cards or `[done]`; `/wip-wall mock` bypasses it. `setupOf` (full, with the Ghostty rows) fills the checklist in the background through `fillSetup`, guarded by `setupRun`. `checking` is the default, so a cached board still paints before the gate answers. `pane.test.tsx` flags `noRoot` (the detect shell prints no root unless `WIP_WALL_SAVED_ROOT` is set) and `authFail` (`glab auth` exits 1).
- One pane across sessions: the session showing the pane writes `pane:owner` `{ sid, at }` at `start`, on `/wip-wall` and on every 30 s liveness tick while its pane is open. `start` opens no pane and starts no polling when another sid wrote it less than `OWNER_STALE_MS` (90 s) ago, so a second Claude in a Ghostty split or window started by hand stays bare; `/wip-wall` there opens a pane anyway and takes the key. `session.end` (not `clear` or `resume`) deletes the key when this session owns it, so the next session opens the pane without waiting. In `pane.test.tsx` the `store.get` mock returns `undefined` for `pane:owner` unless `hides` or a `store.set` gives one.
- The 5-minute refresh and 30-second liveness timers skip their work while no `wip-wall` pane is open (`paneOpen`), so idle Claude sessions do not poll GitLab. In `pane.test.tsx`, `clock.every` periods are held: `tick()` fires one, and `panes` is what `ui.panes` returns.
- A control character in any drawn text makes the engine refuse the whole `ui.render` ("a text child holds a control character"), so the pane goes blank. Error text goes through `messageOf`, which calls `clean`; toasts of stderr call `clean` too.
- Leaving `/wip-wall mock` (a `/wip-wall` while `mocking`) empties `cards`, `local`, `live`, `resumable` and `loadedAt` before refreshing, so a failed refresh never leaves mock cards that write real `hide:` keys. The theme (`ui:theme`) is remembered like `ui:openIn`, `ui:mentions`, `ui:reviews`, `ui:legend` and `ui:compact`.
- A `ui.press` hook (every Button's `onPress`) has a 10 s budget and is cut off past it ("ui.press hook skipped: ran past its 10s budget"), so a press must never wait on the person: `$.ui.ask` from a press loses its answer. Ask with buttons drawn in the pane instead. In `pane.test.tsx`, `openCard($, key, place)` presses a title and then its chooser button, `places(ui)` lists the chooser labels, and `filled` records `prompt.fill` calls.
- `/wip-wall setup host <host>` saves a bare GitLab host (a pasted `https://` and trailing `/` are stripped, a path is refused) as store key `ui:host` (`saveHost`); `detect` passes it as env `WIP_WALL_SAVED_HOST`, so precedence is `WIP_WALL_HOST`, saved host, `GITLAB_HOST`, `glab config get host`; the checklist ends with a faint line naming this command. `setting` matches `^setup(\s|$)`, so a newline or tab after `setup` still counts.
- `/wip-wall setup [folder]` (`setupOf`, `saveRoot` in `gitlab.ts`; `setupView` in `view.tsx`; the `setup` atom, empty `checks` means closed): the clone root is `WIP_WALL_ROOT`, then the store key `ui:root`; there is no default folder, so an unset root makes `settingsOf` throw and the check show ✗. `detect` passes the saved root to the `DETECT` shell as env `WIP_WALL_SAVED_ROOT`, so its output stays four lines; `saveRoot` calls `forgetSettings` or the cached `detected` keeps the old root. The atom is cleared by a plain `/wip-wall`, by `/wip-wall mock` and by `setup:close`. `setupOf` runs in the background (the Ghostty probe can wait on a macOS Automation dialog and a hook has a 10 s budget); `setupRun` is bumped by every `/wip-wall` and by `setup:close`, so a late result never reopens a closed checklist. `pane.test.tsx` reads the saved root through `init.env.WIP_WALL_SAVED_ROOT` and `store.get('ui:root')`, and a test that saves a root restores the fixture root in `finally`. `setupView` draws a faint `clone folder: /wip-wall setup <folder>` line, no buttons (a pressed folder would need its own scan inside the 10 s press budget). `refreshFresh` waits for an in-flight refresh first, which would otherwise land the old root's board.
